# 脚本依赖实现记录

## 实现范围

入口仍为 `Node.exec_script(script, argstr, envs)`。先静态检查全部本地依赖，再交付文件；执行目录为 `Node.scriptdir`，普通 `Node.exec` 的目录规则保持原样。无依赖脚本也使用这个新的脚本执行目录。

- 支持 `source`、`.`、`bash`、`sh` 和直接相对路径命令，递归收集并按共同根目录保留布局。
- 支持单引号、双引号、转义、续行、分号、条件分支、解释器常见选项和脚本参数；排除注释、普通字符串、here-document、数组元素、算术文本和 case 模式。
- 简单常量包括无条件的 `NAME=value`、`export NAME=value` 和 `readonly NAME=value`，支持 `$NAME`、`${NAME}` 及字符串拼接。被 source 的脚本共享已知常量；独立执行的子脚本须自行定义所需常量。
- 条件赋值、循环变量、`read`、追加赋值、数组赋值、复杂变量声明、未知变量、通配符展开、非简单参数展开及运行结果不能作为已知路径；不支持的变量修改会使旧常量失效。远端 source 的变量副作用同样视为未知。命令前的环境赋值不作为后续命令的常量声明。
- 脚本目录白名单包括 `$(dirname "$0")`、`$(dirname "${BASH_SOURCE[0]}")`、`$(dirname "$BASH_SOURCE")`，以及 `$(cd "$(dirname ...)" && pwd)`。允许 dirname 的 `--`、cd 的 `--`/`-P`/`-L`、pwd 的 `-P`/`-L` 和 `CDPATH= cd ...`。对应的简单反引号写法也可静态求值。
- `BASH_SOURCE` 以当前文件为准；被 source 的脚本中 `$0` 保持调用 Shell 的入口语义。普通相对引用始终以共同根目录为准。
- 直接绝对路径及会发生 Shell 展开的未引用、未转义 `~/` 引用交给远端；引号或转义中的 `~/` 按字面量本地路径处理。目录白名单算出的本地绝对路径仍参与本地依赖检查。
- 不运行任何解析阶段的 Shell 或命令替换；缺失文件、循环、父目录引用、根目录外路径及无法确定的引用均在远端操作之前失败。
- 每次调用重新解析并检查远端存在性，只补传缺失文件。每次对必要文件设置执行权限，使先前 chmod 失败后的重试可以恢复。
- 显式声明非 Shell 解释器的入口文件继续作为单文件交付，保留原有执行能力。

## 求值边界

这不是完整的 Shell 解释器。不会静态执行函数、eval、运行时目录切换、间接命令包装或任意命令替换；不解析 `bash/sh -c` 的命令字符串，也不把 `-s` 后的参数当作脚本路径。脚本路径中超出白名单的动态表达式会报错。`--rcfile` 与 `--init-file` 尚不支持，会明确报错。

已有远端文件只按存在性复用，不根据内容更新。SSH 与容器共用 Node 层的交付流程，未增加连接接口或改造连接层日志。

## 验证

全套 65 项 unittest 测试通过。测试从 `Node.exec_script` 观察文件交付、布局、执行结果与错误，包含连接替身和隔离临时目录中的真实本地 Shell。未运行真实 SSH 服务或 Docker 服务验证。

新增解析模块接受严格 mypy 检查。Node 文件的类型检查与起始提交比较：保留原有 5 项类型问题，没有新增问题。

代码审查以 `bce8659` 为基准，分别检查 Standards 和 Spec。审查发现已修复并补充回归测试，两轴复核未解决问题均为 0。
