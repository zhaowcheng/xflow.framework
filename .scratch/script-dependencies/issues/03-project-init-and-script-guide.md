# 03: 交付可用的新项目初始化与脚本编写指南

**What to build:** 项目开发者通过 CLI 初始化得到可由 Pipeline 直接加载的空 Scripts 结构，并从生成项目的 README.md 中了解如何编写目标脚本、声明依赖、定义具名入口及在 Pipeline 中调用；安装包同时交付新模块及模板。

**Blocked by:** 01: 通过项目 Scripts 入口完成脚本执行切换。

**Status:** ready-for-agent

## Acceptance criteria

- [x] 复用 CLI 初始化入口与 CliRunner，在空临时项目实际生成项目结构；模板包含继承框架基类、类定义名为 Scripts、DEPS 为空字典且没有示例脚本入口的项目类，不生成旧 JSON 声明文件。
- [x] 使用 CLI 生成的项目直接构造真实 Pipeline，验证即使没有脚本也能够自动加载项目 Scripts；测试不以仅检查模板文本替代实际加载验证。
- [x] 仅在测试临时项目中按指南添加目标脚本及入口，通过 Pipeline 阶段调用该入口并使用现有 FakeConnection 验证交付、参数及执行结果；生成模板本身仍保持空的入口和依赖声明。
- [x] 在项目初始化模板目录的 README.md 中增加脚本编写指南，初始化后将指南交付到生成项目的 README.md；不另建迁移文档。
- [x] 脚本编写指南说明框架基类、项目 Scripts、Pipeline 与 Node 的职责，以及脚本根目录、目标脚本、脚本入口、依赖脚本和脚本依赖声明的含义。
- [x] 指南展示自定义名称和参数的普通入口、入口内部调用继承的 __exec、类级 DEPS 的直接依赖声明以及 Pipeline 的 self.scripts 调用方式；依赖脚本无需独立入口。
- [x] 明确框架基类与项目子类在定义中都必须名为 Scripts，导入别名不改变类名；不支持任意子类名称，不覆盖框架构造器或执行成员，不要求额外类型注解配置。
- [x] 明确入口自行组装原始 argstr 并处理必要的 Shell 引号，保留 envs、nixenv、CommandResult 和 CommandError 约定，不宣传参数自动映射或完全禁止外部访问内部方法。
- [x] 说明初始化只绑定状态、实际调用才检查依赖，所有项目包括无脚本项目均必须提供项目 Scripts；相关缺失及导入失败在 Pipeline 初始化时暴露。
- [x] 说明递归依赖、上传前预检、路径限制、保留子目录、只执行目标脚本和当次 Node.scriptdir 的规则，以及远端目标存在时直接复用、不补传或自动刷新的行为。
- [x] 指南中的示例仅展示当前 Scripts 接口的脚本编写与调用方式，不包含旧项目迁移步骤，不将旧入口或旧 JSON 声明作为可用接口。
- [x] 实际构建并检查 wheel 和源码分发包，确认包含新框架模块与可用的项目初始化模板；结合实际 CLI 初始化和 Pipeline 加载验证模板契约。
- [x] 运行相关 CLI、Pipeline 及脚本调用回归，验证指南中的调用方式与实际新接口一致；连接替身验证不表述为真实 SSH 或 Docker 集成验证。

## Scope notes

依据本功能已确认的《Scripts 项目脚本接口规格》及用户最新文档范围要求。任务 01 已同步提供切换所必需的最小模板；本任务完善实际新项目使用、模板 README.md 中的脚本编写指南和发行包验证，不编写迁移指南。只依赖任务 01，不依赖任务 02 的多项目及初始化异常场景，两者可以独立推进。
