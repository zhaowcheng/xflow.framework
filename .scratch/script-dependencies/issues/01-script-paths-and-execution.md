# 01: 统一目标脚本的路径与执行目录

**What to build:** 调用者使用相对脚本根目录的路径指定目标脚本。框架从当前 Pipeline 的项目中定位本地脚本，上传时保留相对目录结构，并在当次调用的远端脚本根目录中执行。远端目标脚本已存在时继续直接复用。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [x] 保留 `Node.exec_script(script, argstr, envs)` 的接口形状及返回结果约定；入口统一为相对脚本根目录的路径，不保留旧入口路径语义的兼容分支。
- [x] 本地脚本根目录取当前 Pipeline 项目目录中的脚本目录；改变本地进程工作目录或使用远端 `node.dir(...)` 不改变本地源文件来源。
- [x] 入口的绝对路径及越出脚本根目录的路径被拒绝；非法入口不会触发文件上传或目标脚本执行。
- [x] 无依赖的根目录目标脚本和子目录目标脚本均可首次上传并执行；本地目标文件缺失时明确指出所缺文件，不上传、不执行。
- [x] 本地与远端使用同一相对路径，上传保留子目录结构，按需创建远端父目录，并保留目标脚本上传后的执行权限设置。
- [x] 远端目标脚本已存在时，即使本地目标文件缺失，也直接执行远端目标，不上传、不重新设置执行权限；入口仍需通过路径范围检查。
- [x] 目标脚本的执行工作目录为当次调用的 `Node.scriptdir`；参数、环境变量、现有 `nixenv` 包装、返回结果及执行错误传播符合原约定。
- [x] 普通 `Node.exec` 继续使用 `Node.cwd`；`Node.scriptdir` 仍随 `Node.cwd` 变化，目录上下文结束后恢复现有行为。
- [x] 同步更新方法说明和已有调用示例，明确入口相对脚本根目录以及脚本执行目录的变化。
- [x] 通过公开 `Node.exec_script` 调用验证上传位置、执行目录、复用、参数、环境变量、运行环境包装及结果／错误；更新旧测试的项目外绝对路径语义，不断言内部实现。扩展后的 Node 测试及仓库现有测试套件通过。
