# 03: 让新项目获得依赖声明和使用说明

**What to build:** 用户初始化新项目时自动获得空的脚本依赖声明及使用说明，能够依据说明维护依赖、调用目标脚本并理解远端复用规则；旧项目维护者能够据此调整入口及脚本中的相对路径。

**Blocked by:** None (can start immediately). 模板和说明依据已确认的功能规格交付，可与运行时实现并行。

**Status:** ready-for-agent

- [x] 新项目初始化后，脚本根目录包含 `deps.json`，其内容可解析为空字典 `{}`。
- [x] 模板 README 随项目初始化一起交付，说明脚本依赖声明由脚本编写者维护，并介绍声明格式、直接及间接依赖、共享依赖去重和子目录组织方式。
- [x] 说明 `Node.exec_script` 的入口参数、声明中的路径和脚本之间的引用均相对脚本根目录；绝对路径及越界路径不受支持。
- [x] 说明远端目标不存在时先检查再上传完整集合；已存在时直接复用，不检查本地声明或依赖，也不补传或更新依赖。
- [x] 说明缺少声明文件或目标没有声明条目时按无依赖处理，以及格式错误、所需文件缺失和循环依赖的报错行为。
- [x] 迁移说明明确要求旧入口移除项目目录层级的脚本目录前缀；说明目标在 `Node.scriptdir` 中执行，对相对输入、参数和输出位置的影响，以及普通命令工作目录和远端目录上下文的现有约定。
- [x] 复用已有模板复制和打包机制，确认空声明及模板说明随框架模板交付，不新增独立模板交付流程。
- [x] 通过公开 CLI 初始化命令验证声明及说明生成，保持已有非空项目目录的拒绝行为；扩展后的 CLI 测试及仓库现有测试套件通过。
- [x] 本任务以初始化产物和说明为独立验收对象；运行时依赖解析的行为验收由 01 和 02 覆盖，不以本任务完成表示运行时已实现。
