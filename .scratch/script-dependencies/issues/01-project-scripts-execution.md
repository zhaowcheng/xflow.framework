# 01: 通过项目 Scripts 入口完成脚本执行切换

**What to build:** Pipeline 自动加载当前项目的 Scripts 并绑定当前节点，阶段通过项目自定义的脚本入口执行目标脚本。将已有依赖交付行为迁入框架 Scripts，依赖声明改为项目类的 DEPS；一次切换移除旧入口及旧声明机制，保持现有执行语义。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## Acceptance criteria

- [x] 框架在 xflow.framework.scripts 模块提供原名为 Scripts 的基类。项目脚本包入口定义继承基类且类定义名也为 Scripts 的项目类，普通入口方法可通过继承的 self.__exec 调用统一执行能力。
- [x] 基类构造器包含必选的 node 参数。Pipeline 构造时按自身项目目录加载项目 Scripts，并使用当前节点建立 self.scripts；不要求项目 Pipeline 手动指定类、实例化或增加类型注解配置。
- [x] 初始化只绑定节点，不提前解析或验证 DEPS，不固定尚未就绪的远端目录，不新增脚本相关的远端存在性检查、上传或执行。合法模块中的畸形 DEPS 不使 Pipeline 提前初始化失败。
- [x] 统一执行方法保留 script 的字符串或 Path 输入、原始 argstr 字符串和可选 envs 参数约定，返回 CommandResult。脚本入口自定义名称与参数，明确选择目标脚本并负责参数字符串的 Shell 引号；不新增接受任意脚本路径的公开执行入口。
- [x] DEPS 为脚本相对路径字符串到直接依赖路径字符串列表的类级字典。空字典或没有目标条目时按无声明依赖处理；归一化、遍历与多次调用均不原地修改字典或其中的列表。
- [x] 目标路径按项目脚本根目录解释和归一化；在任何远端目标检查之前拒绝绝对路径、根目录自身、越界路径和逃逸根目录的符号链接。合法内部符号链接保留既有交付语义，相对子目录不丢失。
- [x] 远端目标不存在时，先校验整份 DEPS 的结构及路径，再递归收集目标可达依赖并检查循环，最后检查本次所需文件。全部预检通过后才上传；预检失败不得上传部分集合。
- [x] 直接、间接、重复和共享依赖按归一化相对路径收集并去重。格式和路径合法但不属于目标可达范围的缺失文件或循环不阻止执行。
- [x] 路径、声明及可达循环错误抛出 ValueError，本次所需文件缺失抛出 FileNotFoundError；错误可定位相关条目或文件，循环错误给出循环关系。
- [x] 远端目标不存在时交付完整去重集合，即使部分依赖已存在也不逐项检查或跳过。目标及依赖保留相对子目录，沿用目标脚本的可执行权限处理，框架只执行目标脚本。
- [x] 远端目标存在时，在保留目标路径范围检查的前提下直接执行，不验证 DEPS、不要求本地目标和依赖存在，不补传、不重新设置权限、不刷新内容。覆盖首次交付后的再次复用。
- [x] 每次执行读取当次 Node.scriptdir，不在 Scripts 构造时缓存；正常返回及异常退出都恢复外层目录，普通 Node 命令保持 Node.cwd 语义。
- [x] 原始参数字符串、可选环境变量、nixenv 包装、CommandResult 与非零返回码的 CommandError 保持既有行为；不改变脚本解释器约定。
- [x] 移除 Node.exec_script 与旧 JSON 声明的加载能力，不保留双入口、回退或兼容层；Node 保留上传和命令执行等基础能力。
- [x] 同步提供新项目所必需的最小空 Scripts 模板，不生成旧依赖声明文件，不预置示例入口或依赖条目；现有无脚本的 Pipeline 和 CLI 测试夹具补齐空项目 Scripts，保证切换后的基本项目结构有效。
- [x] 最小使用说明与新接口一致；项目初始化模板 README.md 中的脚本编写指南及发行包中的项目初始化验证由任务 03 完成，不将旧接口保留到后续任务。
- [x] 复用既有行为实现，不引入 Shell 解析器、参数映射系统、通用注册框架或无关重构；已有目录上下文行为作为回归保护，不单独重做。
- [x] 主要验收通过真实 Pipeline 阶段调用自动加载的项目 Scripts 普通入口，使用真实 Node 和现有 FakeConnection 观察上传内容、命令、目录、返回值及异常，不直接测试私有解析函数或固定上传顺序。
- [x] 将既有脚本交付测试迁移到新调用链，并覆盖入口名称与文件名不同、仅作为依赖的脚本没有入口、参数包含空格以及 Pipeline.run 返回 FAILED 的既有生命周期行为。实现和受影响测试共同交付。

## Scope notes

依据本功能已确认的《Scripts 项目脚本接口规格》。本任务承接完整的既有依赖及运行规则，不将已经存在的能力拆成重新设计算法的任务。任务 02 补齐同进程多项目隔离和初始化失败场景；任务 03 完成新项目使用、模板 README.md 中的脚本编写指南和发行包交付验证。
