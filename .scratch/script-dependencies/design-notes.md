# 脚本依赖解析

设计边界已逐项确认，等待用户确认完整方案；尚未实施代码改动。

## 已确定的需求

- 脚本根目录默认是项目根目录下的 `scripts`。
- 由脚本编写者在脚本根目录下的 `deps.json` 中维护脚本依赖声明，不解析脚本内容来推断依赖。
- 新项目模板 `xflow/framework/statics/initdir/scripts/deps.json` 的初始内容为 `{}`。
- 声明示例：`"my_script.sh": ["common/mylib1.sh", "common/mylib2.sh"]`。
- 保留远端目标脚本的存在判断：存在时不重复上传；不存在时一并上传目标脚本和依赖脚本。
- 上传后保留脚本根目录内的相对目录结构。
- `Node.exec_script` 的执行工作目录由 `Node.cwd` 改为 `Node.scriptdir`。
- 脚本引用其他脚本时，始终使用相对脚本根目录的路径。
- 在 `xflow/framework/statics/initdir/README.md` 中说明依赖声明的维护方式，以及脚本引用路径约定。
- 本次保持简单；更复杂的判断逻辑留待后续需求单独设计。
- 递归收集本次目标脚本的直接及间接依赖，同一文件只处理一次。
- 旧项目缺少 `deps.json` 时，按空字典处理。
- 目标脚本需要上传时，先检查声明及本次所需文件；格式错误或文件缺失时明确报错，不上传、不执行。
- 循环依赖视为声明错误，在上传前报错并显示循环路径。
- 依赖声明的键和值必须是相对脚本根目录的路径；禁止绝对路径及通过 `..` 越出根目录。
- 目标脚本必须位于项目 `scripts` 目录内，目录外的目标脚本直接报错，不增加外部脚本的特殊处理分支。
- `Node.exec_script` 的 `script` 参数统一为相对脚本根目录的路径，例如 `my_script.sh` 或 `common/task.sh`，不再使用相对项目目录的 `scripts/` 前缀。

## 第一轮结论

用户选择：递归处理并去重；缺少声明文件时当作无依赖；检查通过后才上传，出错即停止。

## 第二轮结论及澄清

- Q5、Q6：用户同意上传前检测循环依赖，以及依赖声明的路径范围约束。
- Q4：用户在核对依据后，同意统一要求目标脚本位于项目 `scripts` 目录内，目录外直接报错。
- 依据为 `Node.exec_script` 的 `Path(script).absolute()`，没有校验入口脚本是否在项目根目录内；已有单元测试传入项目外临时脚本的绝对路径。
- 此处的绝对路径指本地源文件路径；执行的是上传后的远端 `Node.scriptdir/<文件名>`，不是远端同名绝对路径。
- 方法注释 `xflow/framework/node.py:222` 写的是“本地脚本路径（相对项目目录）”。当前实现允许的范围比注释更宽，不能仅凭此认定项目外脚本是正式约定的用法。
- 用户进一步明确：既然目标限定在脚本根目录内，`exec_script` 的参数也应相对脚本根目录，移除原有调用中的 `scripts/` 前缀。

## 完整方案

1. 本地脚本根目录取项目 `scripts` 目录。调用形式为 `exec_script('my_script.sh', argstr, envs)`；脚本参数必须是相对脚本根目录的路径，禁止绝对路径及越出根目录的路径。
2. 同一相对路径同时用于本地定位、依赖声明匹配及远端定位。例如 `exec_script('common/task.sh')` 读取本地项目 `scripts/common/task.sh`，并映射为远端 `Node.scriptdir/common/task.sh`；声明中的对应键为 `common/task.sh`。
3. 先检查远端目标脚本是否存在。存在时直接执行，不解析依赖、不检查依赖是否缺失，也不补传依赖。
4. 目标不存在时读取本地 `scripts/deps.json`。缺少文件等价于 `{}`；声明为字典，键为脚本根目录内的相对路径，值为依赖脚本相对路径的列表；没有对应条目表示没有声明依赖。
5. 根据声明递归收集目标的直接、间接依赖，按文件路径去重。上传前完成声明格式、路径范围、本次所需文件及循环依赖检查，失败时明确报错，不上传、不执行。
6. 检查通过后上传目标脚本及全部依赖，按需创建远端父目录并保留相对结构。本次不增加逐个依赖的远端存在判断，也不增加内容比较或更新判断。
7. 执行工作目录为本次的 `Node.scriptdir`；保留参数、环境变量及现有 `nixenv` 包装。普通 `Node.exec` 的工作目录保持原行为。
8. 保留 `Node.scriptdir` 当前随 `Node.cwd` 变化的行为，不把远端脚本目录重新设计为固定目录。
9. 新项目模板增加内容为 `{}` 的 `scripts/deps.json`。模板 README 说明依赖声明由脚本作者维护，`exec_script` 参数、声明中的路径及脚本之间的引用均相对脚本根目录，并说明脚本执行工作目录的变化。

执行目录变化会同时影响脚本的相对输入、相对参数及输出文件位置，现有脚本迁移时需要按新目录约定调整。
现有调用需由 `exec_script('scripts/my_script.sh')` 改为 `exec_script('my_script.sh')`；方法注释及调用示例同步更新。
